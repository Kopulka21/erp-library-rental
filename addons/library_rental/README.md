# Модуль library (Практичне заняття 2)

## Структура зв'язків
- **Book → Copy** (One2many / Many2one): одна книга має N фізичних примірників. Книга і примірник — різні сутності.
- **Copy → Loan**: примірник має історію з N видач (не більше 1 активної — обмеження буде у ПЗ 3).
- **Member → Loan**: читач має N видач.
- **Member**: окрема модель library.member (варіант «а»). Чому: читачу потрібні лише ім'я та номер квитка, тому не тягнемо зайві поля res.partner. Втрачаємо готові контактні дані та інтеграцію з рештою Odoo.
- Loan прив'язана до **примірника**, а не до книги, бо видається фізичний екземпляр. Інакше неможливо знати, який саме примірник на руках, і порахувати вільні.

## ondelete
| Поле | Значення | Чому |
|---|---|---|
| Copy.book_id | restrict | не можна мовчки знищити записи про фізичні примірники |

| Loan.member_id | restrict | те саме |
